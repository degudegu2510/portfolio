## プロジェクト概要

**AIサジェスト機能** は、記事の執筆内容をもとに、AI が続きの文章を提案する機能です。Markdown エディタで `/` コマンドから呼び出し、表示された提案を Tab キーで採用できます。

デザイナーとして、企画・設計、プロジェクトマネジメント、UX 設計、UI デザインまでを担当しました。

### 補足情報

* 期間：2023年8月〜2023年11月
* 担当：企画・設計 / プロジェクトマネジメント / UX 設計 / UI デザイン
* チーム体制：2名（デザイナー 1名が PdM・PjM を兼任、エンジニア 1名）
* 使用ツール・技術：Figma / AWS（Amazon Bedrock）/ Qiita の技術スタック
* [Qiita Blog：AIサジェスト機能（クローズドベータ版）](https://blog.qiita.com/ai-suggest-closed-beta/)


## 背景・課題

生成 AI の発達により、さまざまな場面で AI が使われるようになっていました。当時は GitHub Copilot のように、Tab キーを押すだけで続きのコードを提案してくれる体験が広がり始めていた時期です。

Qiita でも、生成 AI を使って、これまで提供できなかった新しい執筆体験をつくれないかを検証することにしました。

## 進め方

1. GitHub Copilot などの先行事例から、エディタ上での AI 補完の体験を調査
2. 提案の見せ方、ローディング、採用の操作など、複数の UI 案を作成
3. 先行事例の体験をベースに UI を決定し、実装
4. 申請制のクローズドベータ版として公開し、利用状況とフィードバックを確認
5. 学びをもとに、呼び出し方を見直し

## デザイン上の判断とその理由

### 「続きを提案する」機能にした

GitHub Copilot の「Tab を押すと続きを提案してくれる」体験を、記事の執筆でも実現できないかと考えました。エンジニアがすでに慣れている体験を文章にも広げることで、新しい操作を覚えなくても使えるようにするためです。

### 操作や見せ方は、GitHub Copilot の体験をベースにした

提案の見せ方やローディングの表現は、いくつかのパターンを作って比較したうえで、GitHub Copilot などのエディタの体験に近づける形で決めました。生成中は「…」のローディングを表示し、完了後に提案を表示しています。

### 自動表示から、`/` コマンドで呼び出す形に見直した

当初は、入力に合わせて自動で提案を表示していました。しかし、文章を書いているときは、ある程度書き終わりまで頭の中で想像できているため、提案の良し悪しがはっきり見えてしまい、採用されにくいことが分かりました。

そこで、続きに **悩んだときにだけ呼び出せる** よう、`/` コマンドで呼び出す形にしました。

## 成果

* 生成 AI を使った執筆体験を、クローズドベータ版として短期間で公開した。
* 採用率は伸びず、だんだんと使われない機能になった。一方で、文章の補完はコードの補完とは違い、書き手がすでに書き終わりを想像できているため提案が採用されにくい、という学びを得られた。
