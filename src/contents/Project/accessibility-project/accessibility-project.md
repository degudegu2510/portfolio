## プロジェクト概要

Qiita のウェブサイト全体を対象に、アクセシビリティの改善に取り組んでいるプロジェクトです。WCAG の適合レベル AA への一部準拠を目標に、重要なページから順にチェックと改善を進めています。

リードとして、プロジェクトのマネジメントとメンバーの育成を担いながら、カラーパレットの設計など、プロダクトの根幹に関わる改善は自分でも手を動かしました。

## 背景・課題

Qiita のミッション「エンジニアを最高に幸せにする」を実現するには、年齢や障害の有無を問わず、あらゆる人が使えることが必要だと考えています。

一方で、アクセシビリティを専門に扱う組織はなく、これまでは各メンバーが他のプロジェクトと並行して自主的に対応していました。そのため、担当者や状況によって対応にばらつきがありました。

* スクリーンリーダーでの読み上げや、キーボードのみでの操作性を確認できていなかった
* ブランドカラーの緑と白の組み合わせなど、コントラスト比が確保できていない箇所があり、色の組み合わせの基準も整理されていなかった
* モーダルウィンドウを開いてもすぐにフォーカスできず、背面の要素を操作できてしまっていた

## 進め方

1. 「セマンティックなマークアップにしよう」など、具体的な行動からメンバーを巻き込む
2. 毎週の勉強会で、アクセシビリティの知識をチームに浸透させる
3. 勉強会で得た知識をもとに、メンバーが対応範囲と基準を考え、リードとして承認する
4. チェックシートで各画面を確認し、問題点を issue 化して順次改善する
5. AI エージェントを活用し、改善を継続的に回せるフローをつくる

## デザイン上の判断とその理由

### 勉強会より先に「具体的な行動」から始めた

「アクセシビリティに取り組もう」と抽象的に呼びかけても、何をすればいいか分からず後回しにされがちです。そこで、まずはすぐに実践できる具体的な行動を提案し、改善の実感を持ってもらってから勉強会を始めました。

### 勉強会は持ち回りで発表する形にした

毎週、メンバーが各自で WCAG などのドキュメントを読んでまとめ、発表する形にしました。一方的に教えるのではなく、自分で読んで人に説明することで、メンバー自身が対応範囲を議論できるだけの知識を身につけられるようにするためです。

### 対応範囲と基準はメンバーに考えてもらった

対応範囲と基準は、勉強会で知識をつけたメンバーに考えてもらい、それを承認する形にしました。メンバーが自分ごととして判断できるようにし、プロジェクトを任せられる人を増やすためです。

### カラーパレットは自分で設計した

Qiita のブランドカラーの緑は、上に白い文字を乗せるとコントラスト比が足りません。一方で、黒い文字を乗せるとブランドガイドラインに反してしまいます。

色はプロダクトの根幹に関わるうえ、色彩とフロントエンドの両方の知見が必要なため、カラーパレットは自分で設計しました。ブランドカラーと UI で使う色を分け、ライトテーマとダークテーマの両方でコントラスト比を確保しています。

### 短期で終わらせず「薄く広く」続ける形にした

専任のメンバーはいないため、短期間で一気に直すのではなく、1〜2年の長期プロジェクトとして位置づけ、2週間に数時間ほどの時間を確保して進める形にしました。他のプロジェクトと並行しながらでも、止めずに続けられるようにするためです。

### AI エージェントに改善を任せる仕組みをつくった

改善を継続的に回すため、チェックで見つかった問題点を、AI エージェントが取り組みやすい形式で issue にまとめ、GitHub Copilot coding agent にプルリクエストを作成させる流れをつくりました。人はチェックとレビューに集中できるようにしています。

## 成果

* 約2年間にわたって改善を続け、相当数の issue を完了した。
* まだ全ページには対応しきれていないものの、アクセシビリティが守られたページが少しずつ増えている。
* 社内のアクセシビリティに対する知識と意識が大きく向上した。
* 取り組みの知見を、記事やカンファレンスでの登壇として社外にも発信した。
