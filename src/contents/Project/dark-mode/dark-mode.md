## プロジェクト概要

Qiita にダークモード（ダークテーマ）を導入したプロジェクトです。約半年間のベータ版を経て、正式版としてリリースしました。

カラーパレットの修正、カラートークンの設計、開発を担当しました。

## 背景・課題

ダークモードに対応するサービスが増え、Qiita にも多くの要望が寄せられていました。

一方で、既存の色にはアクセシビリティの課題がありました。Qiita のブランドカラーである緑（`#55C500`）は、上に白い文字を乗せるとコントラスト比が 2.24 しかなく、基準を満たせません。しかし、黒い文字を乗せるとブランドガイドラインに反してしまいます。

ダークテーマを導入するなら、色の仕組みそのものを見直す必要がありました。そこで、**ダークテーマの導入とアクセシビリティの改善を一緒に進める** ことにしました。

## 進め方

1. ブランドカラーと UI で使う色を分ける方針を決める
2. ライトテーマとダークテーマで共通のカラーパレットを作る
3. カラーパレットをもとに、UI で使うカラートークンを設計する
4. 各トークンのコントラスト比を検証し、使える組み合わせを表で管理する
5. ベータ版として公開し、対応ページを段階的に広げる

## デザイン上の判断とその理由

### ブランドカラーと UI で使う色を分けた

最初に、**ブランドカラーをそのまま UI のカラーパレットには使わない** と決めました。ブランドカラーはブランドとしての表現に使い、UI ではコントラスト比を満たす色をカラートークンとして使う形にしています。ブランドを守ることと、誰でも読めることを両立するためです。

### カラーパレットとカラートークンの2層にした

使える色の一覧である **カラーパレット** と、UI のどこで使うかを表す **カラートークン** を分けました。カラーパレットはグレー、グリーン、ブルー、イエロー、レッドの5スケールで構成しています。

カラートークンは、背景（Base）、ボタンなどの背景（Container）、文字（Text）、枠線（Border）の役割で分けています。Markdown の中など、特定のコンポーネントでしか使わない色は別のトークンとして管理し、拡張しやすくしました。

### ライトテーマとダークテーマで同じカラーパレットを使った

テーマごとに別のパレットを持つと、管理の負荷が大きくなります。そこで、両テーマで同じカラーパレットを使い、トークンの割り当てだけをテーマごとに変える形にしました。

同じ輝度の差でも、ライトテーマとダークテーマでは見た目の色の差が変わります。そのため、輝度を等間隔にせず、見た目の差がそろうように調整しています。

### コントラスト比を表で管理した

トークンを1つずつ確認し、「この色より濃い色の上なら使ってよい」「この組み合わせは使ってはいけない」といったルールを表で管理し、カラートークンに落とし込みました。デザイナーが都度判断しなくても、アクセシビリティを守れるようにするためです。

### 対応ページを段階的に広げた

Qiita はページ数が多く、一度にすべてを切り替えるのは大変です。そのため、記事ページから始めて、フィード、ユーザー・タグ、質問、検索・通知・設定、エディタと、ベータ版で使用感のフィードバックを集めながら段階的に広げました。

## 成果

* ダークテーマを正式版としてリリースし、OS の設定に連動する「システムのテーマ」と「ライトテーマ」を選べるようにした。
* 色に関する不満がほとんど聞かれなくなった。
* ここで設計したカラートークンは、その後のアクセシビリティ改善プロジェクトの土台にもなった。
