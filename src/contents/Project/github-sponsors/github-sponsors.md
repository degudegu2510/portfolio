## プロジェクト概要

**GitHub Sponsors 連携機能** は、GitHub Sponsors を利用している人が、Qiita 上の活動でも支援を受け取りやすくするための機能です。

機能の企画・設計と、プロジェクトマネジメントを担当しました。

### 補足情報

* 期間：2023年11月〜2024年1月
* 担当：企画・設計 / プロジェクトマネジメント
* チーム体制：4名（PdM・PjM 1名、デザイナー 1名、エンジニア 2名）
* 使用ツール・技術：Figma / Qiita の技術スタック
* [Qiita Blog：GitHub Sponsors との連携機能](https://blog.qiita.com/github-sponsors/)


## 背景・課題

他の技術記事プラットフォームの登場により、記事を通じて投げ銭などの支援を受け取りたいユーザーが増えていました。また、「いいね」以上に感謝や応援を伝えたいという声もありました。

一方で、Qiita の中に投げ銭機能を作るには、法務的にグレーな部分がありました。上場企業グループとして、そのリスクを取って自社で投げ銭機能を持つことは難しい状況でした。

さらに他社の事例を調べると、記事の投稿で収益を得ている人はそれほど多くありませんでした。自社で本格的に投げ銭機能を運営すると、トラブルの対応や運営のコストも増えるため、現実的ではないと判断しました。

## 進め方

1. 他社事例の調査と、投げ銭機能の実現方法の比較検討
2. 法務的な確認と、社内での意思決定のすり合わせ
3. GitHub Sponsors と連携する方針の決定
4. デザインと実装
5. リリース

## デザイン上の判断とその理由

### 自社の投げ銭機能ではなく、GitHub Sponsors と連携した

エンジニアにとって身近で、Qiita と相性のよいサービスである GitHub Sponsors と連携することで、**法務的なリスクや運営のコストを抑えながら、支援を受け取れる仕組み** をつくりました。

### 支援の案内を記事の下に配置した

支援の案内は、記事を読み終えた人が自然に目にする記事の下と、マイページのサイドバーに配置しました。多くのサービスで記事の下に置かれていることもあり、読者が迷わず見つけられる位置にしています。

### 表示の ON/OFF とメッセージを設定できるようにした

支援を受け取ることは、書き手にとって感謝の気持ちを伝える機会でもあります。そのため、支援エリアに自分の言葉でメッセージを書けるようにしました。

一方で、支援を受け取りたくない人もいます。記事の下には広告枠もあるため、表示を望まない人は OFF にできるようにしました。

## 成果

* 法務面の確認と意思決定を固めたうえで、デザインと実装は短期間で進め、約3か月でリリースした。
* 一定数のユーザーに使われる機能になり、反響もよかった。
