## プロジェクト概要

[Qiita for Business](https://business.qiita.com/) は、エンジニア採用や技術広報を担う企業に向けて、Qiita の広告メニューを紹介するサイトです。

本プロジェクトでは、**Qiita 広告の申し込みを増やす** ことを目的に、LP の改善を行いました。課題の特定から設計、実装、テスト、リリース、効果検証までを一人で担当しています。

### 補足情報

* 期間：2026年7月〜2026年8月
* 担当：1名（リサーチ / 要件定義 / 情報設計 / UI デザイン / 実装 / 検証）
* 利用者：エンジニア採用や技術広報を担う企業のマーケティング・広報・人事担当者
* 使用ツール・技術：GitHub / Claude Code / Pen.dev / Astro / TypeScript / Tailwind CSS / AWS（S3 + CloudFront）/ GA4 / GTM / Pardot
* [Qiita for Business](https://business.qiita.com/)


## 課題

* LP への訪問数が少なかった。
* WordPress 環境では、ビジネスメンバーが AI を使ってコンテンツを追加・更新しづらかった。

## 進め方

1. セールスへのヒアリング
2. コンテンツの整理
3. 情報設計の見直し、デザイン制作
4. WordPress から Astro でサイトを再構築
5. リリース

## デザイン上の判断とその理由

### 目的別の広告メニュー

広告メニューを商品の一覧から **「目的別」の構成** に変更し、目的ごとに利用シーンが伝わる商品イメージ画像を生成して配置しました。

担当者は「どの商品か」ではなく、「エンジニア採用を強化したい」「イベントに集客したい」といった自社の課題から検討を始めます。そのため、目的から自社に合うメニューを選べるようにしました。

### 検索キーワードを起点にした構成

担当者が課題や目的に沿って検索するキーワード（例：「エンジニア 採用」「エンジニア イベント」）を起点に、ページ構成と見出しを設計しました。

広告の検討は検索から始まることが多いため、デザインと SEO を切り離さず、検索流入から目的別メニューへ自然につながる導線にしています。

### 申し込みから商談までをつなぐフロー

申し込み後、目的に応じて担当のセールスメンバーと直接日程を確保できるフローを設計しました。

申し込みから商談設定までのやり取りを減らし、担当者の検討熱が高いうちに商談につなげるためです。あわせて、セールス側の日程調整の工数も削減しました。

## 成果

* 目的別キーワードを起点にした構成により、検索流入が増加した。
* WordPress から Astro へ移行し、ビジネスメンバーが AI 主導で SEO コンテンツを制作・追加できる運用体制を構築した。エンジニアやデザイナーに依頼せず、ビジネスメンバー自身がコンテンツを追加・更新できるようになった。
* 申し込みから商談の日程確保までを一つのフローにまとめ、セールスの日程調整の工数を削減した。
