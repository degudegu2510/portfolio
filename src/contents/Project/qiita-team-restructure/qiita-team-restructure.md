## プロジェクト概要

**Qiita Team** は、企業やチームが社内の情報共有・ナレッジ蓄積に使う、法人向けのドキュメントコラボレーションサービスです。

本プロジェクトでは、利用人数や記事数が増えても情報共有・コミュニケーションが円滑にできるよう、サービス全体を **「グループ起点」の構造** に再設計しました。デザイナーとして、情報設計から UI/UX デザイン、フロントエンド実装までを担当しています。

### 補足情報

* 期間：2021年9月〜2022年6月
* 担当：デザイナー（情報設計 / UI/UX デザイン / フロントエンド実装）
* チーム体制：5名（プロジェクトリーダー兼エンジニア、エンジニア、マーケター、デザイナー）
* 利用者：Qiita Team を導入している企業・チームのメンバー、およびチームの管理者
* 使用ツール・技術：Figma / React / TypeScript / Emotion / HTML / CSS
* [Qiita Team、新UIのオープンベータ版を公開（プレスリリース）](https://corp.qiita.com/releases/2022/04/qiita-team-update-beta/)
* [Qiita Team UI アップデートの内容と注意点](https://team-docs.qiita.com/QiitaTeam/items/c3e657622a4689a27389)


## 課題

ある1,000人規模の大規模組織への導入をきっかけに、利用人数が増えたときの運用課題が浮き彫りになりました。

* 新着の記事が大量に流れ、必要な情報を見落とす、キャッチアップに時間がかかる
* 記事が増えるほど、目当ての記事にたどり着くまでに時間がかかる
* チームメンバーやグループの管理にコストがかかり、権限も細かく設定できない

既存の UI はグループ機能の活用を前提にした設計になっておらず、多くのユーザーが全記事を1か所で管理していました。

事業としては、大規模組織でも使い続けられる状態（継続率の向上）と、エンタープライズ企業の新規獲得を目指していました。

## 進め方

1. 課題の整理とスコープの決定（第一弾は主要ページに限定し、階層構造や組織情報の連携はスコープ外とした）
2. Figma で情報設計と UI デザインを行い、チーム内で議論しながら仕様を固める
3. フロントエンドの実装
4. 段階的にリリースし、フィードバックを集めながら改善
   * 2021年12月 社内リリース
   * 2022年1月 重要顧客向けクローズドベータ
   * 2022年3月 全企業向けオープンベータ（新旧 UI を切り替え可能）
   * 2022年6月 正式リリース

## デザイン上の判断とその理由

### グループ起点の UI

サービス全体を「グループ起点」の UI に再設計しました。ヘッダー下のグローバルメニューを廃止し、参加中のグループ一覧を左サイドバーに配置しています。

グループごとに情報を分けることで、人数や記事が増えても必要な情報にアクセスしやすくするためです。また、グループという限られたスコープで投稿できることで、大人数の前で投稿する心理的なハードルを下げ、投稿を促進する狙いもあります。

### 既存の記事を General グループに統合

全体に投稿された記事を「General」グループとして扱い、既存の記事もグループの枠組みに統合しました。

既存ユーザーの運用を壊さずに、新しいグループ起点の構造へ移行できるようにするためです。

### よく使う導線をサイドバーに集約

プロジェクト、ストック、下書き、タグ、メンバーへの導線をサイドバーに集約し、よくアクセスする情報を上部に配置しました。トップページの「進行中のプロジェクト」と「人気記事」は廃止し、閲覧履歴などもサイドバーには載せないと判断しています。

日常業務で頻繁に使う導線を一か所にまとめ、迷わず目的の情報にたどり着けるようにするためです。

### 新旧 UI を切り替えられるベータ版

新旧 UI をユーザーごとにいつでも切り替えられるオープンベータ版として提供しました。

毎日の業務で使うツールの大きな UI 変更は、利用者の混乱や解約につながるリスクがあるためです。段階的に移行できるようにし、フィードバックを集めながら改善できる形にしました。

## 成果

* リニューアル後、新たに別の従業員1,000名以上の企業への導入も決まり、売上の成長に貢献した。
* サービス全体の構造と UI を大きく変更したが、段階的なリリースにより、大きな反発や解約を招くことなく既存ユーザーの移行を完了できた。
